================================================================================
1. ROLES & ACCESS MODEL
================================================================================
  - Roles: admin, staff, customer (always lowercase; normalised at boundary)
  - Guest (anonymous): browse home/shop/product, local cart & wishlist,
    policies, about
  - Customer: checkout, orders, addresses, reviews, chat, notifications
  - Staff: dashboard, orders (fulfilment status), inventory (full product
    CRUD + stock), support desk chats (accept-queue model)
  - Admin: everything staff can do + users, roles, coupons, analytics,
    reviews moderation, CMS (hero slides, super grains, appearance),
    PIN-code delivery config, refunds, support inbox (any chat)
  - Frontend ProtectedRoute with allowedRoles per route
  - Backend middlewares: verifyToken, optionalAuth, isStaff, isAdmin,
    cronOrAdmin
  - Deactivated (isActive=false) accounts rejected at token verification

2. APP SHELL, ROUTING & LAYOUTS
================================================================================
  - Centralised route table (routes.jsx) with React.lazy + Suspense
    "Loadable" wrapper for every page (code splitting)
  - Route-level errorElement (RouteError) for render errors & failed
    lazy-chunk loads
  - Global ErrorBoundary ("Something went wrong" fallback) that reports to
    the backend /api/client-errors
  - 404 NotFound page (catch-all route)
  - Three layouts:
      * CustomerLayout — header, search w/ autocomplete, cart/wishlist
        badges, notification bell, footer (social links, newsletter signup
        with email validation), chat widget, cookie consent
      * StaffLayout — sidebar/drawer nav, mobile drawer auto-close on route
        change, light/dark theme toggle persisted in localStorage
      * AdminLayout — sidebar nav, mobile menu, theme toggle, static
        background (no infinite animations for GPU savings)
  - Route map:
      Public:   /login /register /forgot-password /reset-password
      Customer: /  /shop  /cart  /product/:id  /wishlist  /policies
                /policies/:slug  /checkout* /orders* /addresses*
                (* = protected: customer|admin)
      Staff:    /staff  /staff/orders  /staff/inventory  /staff/chats
      Admin:    /admin  /admin/products  /admin/super-grains  /admin/orders
                /admin/users  /admin/analytics  /admin/reviews
                /admin/chats  /admin/hero-slides  /admin/appearance
                /admin/cookies-analytics  /admin/coupon-codes
                /admin/pincode-delivery
  - Hash-segment scrolling & scroll-to-top on route change; browser scroll
    restoration disabled for controlled behaviour

3. AUTHENTICATION SCREENS
================================================================================
  - Shared AuthScaffold (brand panel w/ admin-customisable background image)
  - Register: full name, email, password; email OTP verification step;
    password strength rule (8+ chars, uppercase, etc.); resend-OTP timer
  - Login: two-step — email+password, then 6-digit emailed OTP (input-otp);
    back-compat path if server returns a token directly; role-based redirect
    (admin → /admin, staff → /staff, customer → /)
  - Forgot Password: request reset code (non-enumerating "if that account
    exists" message); resend with cooldown
  - Reset Password: email + OTP + new password + confirm; mismatch & length
    validation
  - useOtpTimer hook for resend countdowns
  - Session stored in localStorage (token, role, userEmail, userName)
  - Global 401 handling → "Session expired" toast + forced logout;
    403 keeps session and surfaces message

15. SERVER CORE & PLATFORM
================================================================================
  - Boot-time env validation (fail fast; extra required vars in production)
  - Warns loudly if SMTP not configured
  - trust proxy hops configurable (TRUST_PROXY_HOPS) for real client IP
  - Helmet with CSP allowing Razorpay
  - Server-generated X-Request-ID per request (inbound header ignored)
  - Morgan access log with request id
  - CORS allow-list (fail closed), env-driven
  - Raw body for Razorpay webhook (HMAC), larger JSON limit (3 MB) only on
    image-carrying routes, 256 KB default
  - Global rate limiter on /api + per-route limiters
  - /health endpoint with real Firestore round-trip (ok / degraded 503)
  - 404 + centralised error handler (no stack traces leaked, requestId on
    every response)
  - Socket.IO server sharing CORS config; io exposed to REST routes
  - Process safety nets (unhandledRejection, uncaughtException → exit)
  - Graceful shutdown on SIGTERM/SIGINT with 10s force timeout
  - App exported for tests (listen only when run directly)

================================================================================
16. AUTHENTICATION & USER MANAGEMENT
================================================================================
  - Firebase Auth via Identity Toolkit REST (signInWithPassword) server-side
  - Registration with email OTP verification
  - Login = password + mandatory emailed OTP (2FA for every role);
    pending session stored server-side until OTP verified
  - Per-account login lockout (8 attempts → 15 min) on top of IP limiter
  - OTP system: crypto-strong 6 digits, stored as sha256(otp + pepper),
    10-min TTL, 5 attempts → 15-min lock, transactional counter,
    timing-safe compare
  - Password reset via OTP (non-enumerating responses)
  - Logout (token revocation)
  - Auto-create missing Firestore profile for existing Auth users
  - Shared token verifier for HTTP + Socket.IO; short-TTL (60s) user cache
    with invalidation on role/status change
  - User profile get/update (whitelisted fields: name, phone, photoURL,
    preferences)
  - Admin: list users (paginated), create user, set role, toggle active,
    soft delete, hard delete — all audit-logged

================================================================================
19. ORDERS, PAYMENTS, STOCK RESERVATIONS & REFUNDS
================================================================================
  - Order state machine: payment_pending, payment_successful_no_stock,
    pending, processing, packed, shipped, out_for_delivery, delivered,
    cancelled, refunded — with explicit allowed transitions
  - Create order: authoritative server subtotal (items built from product
    docs, never client), server-side delivery fee, coupon discount,
    sanitised customer info
  - Firestore transaction: stock check per variant, decrement, coupon
    consume, order + stock reservation (10 min) creation
  - Idempotency key claimed in-transaction (no duplicate orders)
  - Razorpay: create order, client verify (signature), webhook (HMAC raw
    body, event de-dup, payment.captured confirmation, dashboard refund
    reconciliation)
  - Abandon-payment endpoint releases reservation immediately
  - Reservation cleanup endpoint (cron secret or admin) for expired holds
  - Order reads: all (staff, filters + pagination), by email, my orders,
    by id (owner or staff)
  - Status update (staff) with transition validation, notifications, emails
  - Refund (admin only) via Razorpay, from refundable states; reverses
    sales analytics
  - Sharded sales analytics increments/decrements in the same transaction

  - Methods: standard, fastest; fee clamped 0–5000

    fastest fee/ETA/cutoff, min/max order value, serviceByDefault
  - Indian PIN validation (6 digits, no leading zero)
  - Admin: summary, list/search, create (single or bulk items), update,
    status toggle, delete, bulk actions, CSV import/export (5000 rows max)
    — audit-logged
  - Public: states list, cities by state (search, limit), PIN info,
    delivery options for PIN + subtotal
  - India state/city dataset trimmed into committed JSON (~49 KB), city ↔
    state membership validation

27. OBSERVABILITY, RELIABILITY & OPS
================================================================================

  - Error forwarding to webhook (Slack/Discord/Better Stack), size-capped
